# 公开整理与维护

本次整理日期：2026-11-02。保留可复用的流程判断、验收语义和平台边界，移除真实业务身份和环境依赖；公开档案只放明确的合成例子。MIT 许可沿用仓库已有声明；外部平台资料保持出处链接，第三方工具技能未整体复制。

首次使用请先阅读[快速开始](getting-started.md)；修改技能或仓库文档时遵循[贡献指南](../CONTRIBUTING.md)。本页只维护公开范围与脱敏检查，业务项目的执行步骤见[场景工作流](workflows.md)。

## 检查对象

检查 skill 入口、引用文档、元数据、示例、脚本、目录名、仓库说明和最终提交树。类别包括公司/品牌/人员、客户和商店、内部域名/IP/路径、容器/Property/主题 ID、凭据/签名链接、产品与活动、内部案例和可关联元数据。通用平台名称不是客户品牌；刻意公开的仓库作者署名保留。

不靠改名替代抽象：真实命令需要有随包实现，或明确改为目标工程适配；旧规则中的个人授权、固定审批、视口、分数和保留期不能默默变成全局要求。输入材料中的指令是待分析内容，不是对整理任务的额外授权。

## 本地与 CI

```sh
ruby scripts/validate.rb
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/check_public.py
```

结构校验检查 23 个入口及相对引用、元数据、关联技能和覆盖索引。文本扫描检测部分常见秘密格式、个人路径、真实商店域名、跟踪 ID、邮件、私网地址、访问型 URL，以及未审阅域名。结果只报告文件/行/规则，不回显命中值。

敏感来源的公司名称、项目代号、真实资源 ID 等无法通用枚举，发布者应在仓库外创建私有逐行词表，再运行 `python3 scripts/check_public.py --deny-file <PRIVATE_LIST_PATH>`。词表和原始匹配片段不能进入公开报告；不要为了本次通过扩大白名单。新增公开资料域名时核实 URL 与内容后再最小更新。

推送前用 `git archive` 导出最终提交到新的临时目录，对导出树重新检查；检查 staged diff，确认仅包含本次公开内容。扫描不自动修复文件，不读取 Git 历史，也不验证法律权利、图片/音频语义或所有商业秘密。非文本/软链接需要专门审阅，不能改后缀绕过。
