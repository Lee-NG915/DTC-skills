# 快速开始

本指南从取得技能仓库到完成第一轮项目任务。技能由 AI 助手读取并执行；本仓库没有“启动全部工作流”的命令。

## 1. 准备两个位置

- **技能仓库**：存放通用指令、参考资料、合成示例与校验脚本。
- **目标项目**：实际要修改的代码、需求、设计、测试与交付记录所在位置。

两者可以并列放置。不要因为任务在技能仓库中发起，就把业务代码或真实项目档案写进这个公开仓库。

```sh
git clone https://github.com/Lee-NG915/DTC-skills.git
cd DTC-skills
git rev-parse --short HEAD
```

记录输出的版本。使用未合并 PR 时，先按该 PR 提供的分支/提交信息检出；不要把默认分支内容误认为 PR 内容。读取技能只需助手具备文件访问能力；浏览器、Figma、构建或远端平台工具按任务需要提供，不要求一次接入全部工具。

## 2. 让助手读取技能

### 显式路径：适合首次使用

将实际技能仓库路径和目标项目位置告诉助手，明确读取 `skills/dtc-context/SKILL.md`。例如：

```text
技能仓库位置：<DTC_SKILLS_ROOT>
目标项目位置：<TARGET_PROJECT_ROOT>
请先读取技能仓库中的 skills/dtc-context/SKILL.md，
再读取目标项目的规范和本次任务相关资料。
本次目标：检查已有商品卡的移动端布局，只输出问题和最小修正方案。
范围：指定商品卡及其直接依赖；不修改代码或平台配置。
```

这条请求只做检查/方案；若希望实际修复，在请求中明确说明允许修改的范围。无需提供访问令牌；工具认证使用当前环境安全配置。

### 客户端自动发现：按客户端实际能力配置

支持技能自动发现的客户端，可按其当前文档配置目录或链接。成功 clone 只代表文件已下载，不证明已经安装、发现或触发。

本包存在同级技能引用及指向根级 `targets/`、`docs/` 的相对引用，因此优先保留完整仓库结构。若客户端读取链接时不解析真实路径，或只复制单个技能目录，可能破坏引用；核对实际解析结果。不能保持引用时，回到显式读取仓库路径，不反复复制出多份维护源。

加载后检查助手是否能说明当前技能职责、目标项目、实际规则路径和下一步。只显示技能名字不等于引用资料已读取，更不等于任务已执行。

## 3. 建立最小目标档案

项目已有规范和有效上下文时直接复用；重复使用多个技能时，目标档案可以减少反复说明。完整字段见[档案契约](../targets/README.md)。

1. 在目标项目已有文档中查找同类档案；有则明确其位置，不新建第二份。
2. 没有时，将[合成模板](../targets/web-app.example.md)复制到目标项目的 `.dtc/target-profile.md` 或项目指定位置。
3. 记录真实框架、源码归属、已有命令、预览/测试能力和交付层级。未核实项保持未知。
4. 真实项目名称、内部路径和环境身份留在目标项目受控范围；不要提交回公开技能仓库。是否纳入目标项目 Git 由该项目规则决定。

Unix 环境可从技能仓库根执行以下复制示例。先替换目标路径；示例先检查档案是否存在，已有文件或链接保持不变：

```sh
DTC_SKILLS_ROOT="$(pwd)"
TARGET_PROJECT_ROOT="/path/to/your-project"
if test -d "$TARGET_PROJECT_ROOT"; then
  mkdir -p "$TARGET_PROJECT_ROOT/.dtc"
  PROFILE_PATH="$TARGET_PROJECT_ROOT/.dtc/target-profile.md"
  if test ! -e "$PROFILE_PATH" && test ! -L "$PROFILE_PATH"; then
    cp -n "$DTC_SKILLS_ROOT/targets/web-app.example.md" "$PROFILE_PATH"
  fi
else
  printf '目标项目不存在，请先修改 TARGET_PROJECT_ROOT。\n' >&2
  false
fi
```

复制只建立草稿，没有验证目标项目，也没有安装运行器。未知命令应先查项目配置/帮助；不要将另一项目的命令或模板中的示意值填写为“已验证”。

## 4. 发起一项具体任务

至少给出：要改变什么、哪个项目/范围、可用依据和本次允许执行到哪一层。没有的资料说明缺失，不必为局部改动先补完整 PRD。

```text
请使用 dtc-context 和当前任务相关的 DTC 技能完成以下工作。

目标：给现有商品卡增加可选副标题。
范围：商品卡组件及必要的预览/测试，保留现有价格和购买行为。
依据：项目当前组件；副标题为空时不占空间，长内容不能挡住按钮。
本次交付：完成源码修改和本地验证，提供可访问的现有预览入口。
请先检查目标档案与实现，沿用有效决定，记录仍需平台验证的部分。
```

助手应按实际影响选择规格、实现和验证，优先复用项目工具；不会因为示例提到预览就默认安装 Storybook。其他场景的请求与选择方法见[工作流指南](workflows.md)。

## 5. 核对交付与继续任务

交付应能回答：改了什么、依据是什么、哪个版本接受了哪些检查、还有什么未完成。代码存在、预览能开、测试通过和用户接受分别记录。

继续任务时提供原记录/候选及新的目标，例如：

```text
继续同一需求，请先读取原记录的当前状态和下一步证据，
核对工作区是否变化。沿用已确认的副标题规则，只处理长文案换行问题，
更新原记录并复跑受影响的检查，不重新建立整套需求文档。
```

## 6. 维护与更新技能仓库

在技能仓库中先检查 `git status`、当前分支和 upstream，确认没有未保存工作；再按实际来源获取新版本。不要用无条件 reset/覆盖来更新。团队需要可复现流程时，记录使用的提交及目标档案版本；切换版本后核对引用与已变规则。

只更新技能库并不代表目标项目已经应用新规则或补跑验证。维护本仓库内容的方法见[贡献指南](../CONTRIBUTING.md)。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 需要先安装所有工具吗？ | 不需要。读取指令即可开始；只在所选任务需要时使用已有浏览器、设计、构建或平台能力。 |
| 能只用一个技能吗？ | 可以。提供它需要的输入，相关技能只按需读取；注意保留引用结构。 |
| 没有目标档案或完整 PRD？ | 先调查项目和当前目标，形成最小上下文；未决项保留，不编造事实。 |
| 没有 Figma 或无法访问设计稿？ | 可以使用页面、现有组件或用户提供资料，标明来源；截图不能冒充精确结构化取证。 |
| 没有 Storybook/自动化测试？ | 使用现有 preview/harness 或可复现手工步骤，明确覆盖和缺口。 |
| 示例命令运行失败？ | 先确认执行目录、运行时和实际项目脚本；技能库检查命令不是目标项目的 build/test。 |
| 相对引用丢失？ | 检查是否只复制了一个入口或客户端改变了解析路径，优先恢复完整仓库结构。 |
| 为什么仍有待验收？ | 本地结果不能证明真实平台、业务签收或发布；查交付记录中具体缺失层级。 |
| 能自动发布商店、GTM 或生产应用吗？ | 技能包不提供这类执行器。调用环境须提供能力，具体目标和操作沿用当前授权。 |
| 项目规范与模板不同？ | 使用项目实际规范及当前决定；档案只记事实，不授予权限或覆盖项目边界。 |

## 可选：从任意工作区收录 GitHub 项目

[nb-project-upload](../skills/nb-project-upload/SKILL.md) 自包含，可单独复制整个技能目录；它不要求 nb-project 源码或 `.dtc/target-profile.md`。上传只需 Python 3 标准库，目标站已部署受保护收录 API，并在当前进程安全配置 `NB_PROJECT_URL` 与 `NB_PROJECT_INGEST_TOKEN`。示例变量见 [.env.example](../.env.example)，脚本不会自动读取该文件。

```text
请读取 <DTC_SKILLS_ROOT>/skills/nb-project-upload/SKILL.md。
将我提供的 GitHub 项目整理为分类条目并收录到 NB_PROJECT_URL 对应的站点，
凭证使用环境中的 NB_PROJECT_INGEST_TOKEN。先预检，再执行新增并回读。
已有条目保持原文案，分别报告新增、已存在和未确认的结果。
项目清单：<填写实际 GitHub 仓库 URL>
```

只想整理时明确写“只输出条目 JSON，不上传”；只想核对时写“只执行 dry-run”。接口未部署、凭证缺失或写入结果未知时，按技能的停止条件处理；本地测试通过不能证明目标站已上线。
