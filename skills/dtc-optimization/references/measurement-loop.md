# 优化假设与迭代记录

| 项 | 要求 |
| --- | --- |
| 问题 | 可复现症状、影响用户/消费者、候选和触发条件 |
| 基线 | 设备/渲染器、数据、网络/缓存、构建模式、工具版本、原始测量方法 |
| 假设 | 哪个原因造成问题，最小改动预计改变哪个指标；数值目标无依据就写待定 |
| 修改 | 实际 diff、影响组件/样式/生命周期、回滚路径 |
| 对照 | 同条件、足够重复观察、样本量/波动；不是把冷缓存和热缓存当改进 |
| 护栏 | UI 目标、业务交互、输入语义、无障碍与旧消费者不能回归 |
| 结论 | 改善/无证据/回归/待观察；无收益或风险过大撤回或暂停 |

资源完整性（身份/比例/加载）与性能（体积/时延/内存）分开。格式后缀、大体积或非空均不等于高质量。按项目实际工具测量，不能把实验室一台机器结果泛化为所有用户体验。

每轮保留 issueId、来源/候选、cycle/attempt、症状、已证实或推测原因、改动、相关检查、最终状态。变更正确但环境缺证据时标待验，避免无限微调。用户改目标是新决定，提取原值错误是取证修正，两者不要混入缺陷返工统计。

达到采用目标且受影响检查通过就结束修复循环；新增证据才开启下一轮。技术优化建议不改变用户业务范围，也不自动增加参数、换框架或发起后台任务。
