# Web 界面静态审计

用户要求 UI、UX、无障碍或 Web 代码审查时使用。输入应为明确的文件、目录或 diff；无法确定范围时只澄清范围，不默认扫描整仓。读取项目上下文和直接依赖，记录候选、规则版本及是否包含生成文件。

## 检查面

- 语义：动作/导航使用适合的原生元素；控件有可理解的可访问名称；图片的文字替代符合用途；标题/区域关系合理。
- 键盘和焦点：交互可到达且能操作；焦点可见、不被浮层遮挡；弹窗的进入/退出与恢复路径明确；关键操作有手势之外的方式。
- 表单和异步状态：标签、错误、加载、禁用、成功和恢复可感知；检查空值、长文本、粘贴与适用的输入语义。
- 布局与媒体：尺寸或比例稳定；容器可收缩；检查窄屏、长词、裁切、滚动和重排；首屏与非首屏加载策略有依据。
- 动效与性能：减少动态效果的偏好被尊重；检查不必要的同步脚本、反复布局读写、过宽的 transition、资源预算及格式化策略。

静态代码只支持静态结论。实际键盘路径、对比度、字体加载、内容数据、第三方接口和平台编辑器行为需要运行证据，不能在未运行时标为通过。测试或实现转 [组件测试](../dtc-component-testing/SKILL.md) / [实现](../dtc-implementation/SKILL.md)。

## 发现格式

每条为 `文件:实际行号｜规则类别｜触发条件｜具体后果｜证据｜最小修正`。优先级按影响和可达性判断；无证据的怀疑列为待验证，不用风格偏好冒充功能缺陷。无发现时只说本范围未发现静态问题，不宣称全面符合无障碍标准。

本清单是本仓库维护的实践基线，不是标准认证。查标准或更新规则时记录所用版本与适用条款；可从 [W3C 表单标签教程](https://www.w3.org/WAI/tutorials/forms/labels/) 核对标签语义，不把外部规则更新无记录地应用到历史结论。
