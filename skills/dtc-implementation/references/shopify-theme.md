# Shopify 主题组件适配

消费项目真实 Liquid/Schema 约定，不携带其他品牌的前缀、视口、默认商品、主题家族或编辑器授权。主题组件实现不自动上传，也不顺带新增首页实例或改保存配置。

## 来源、业务与配置

静态图只提供可见目标，不能决定平铺/轮播、默认项、滑动和商品绑定。混合依据按视觉、交互、数据、字体和配置分别采用；参考旧组件时保留相关业务能力，冲突或未决高影响规则才澄清。默认值、空值和模式变化必须明确，不套统一的空文本、颜色或宽度策略。

作用于购买对象、价格、优惠或权益的选择，先用具体场景解释展示与实际结果的风险，再记录用户选择；无依据的假设不转成审批清单。开发规格、实现、UI 还原、配置参数和组合场景分别记录。

局部文案强调优先使用平台允许的富文本语义（如 strong）；不硬编码默认短语或字符索引。不为此批量迁移无关字段，也不放开任意 HTML；已有保存值兼容、安全处理和实际编辑器能力必须检查。

## 同一生产契约的预览

有 Storybook/等价 preview 时优先加载真实生产 Liquid、CSS、JS，并用显式适配器提供平台对象。不要复制一套看起来相同的 HTML/业务逻辑。无法渲染真实源码时明确模拟边界，不能声称预览证明生产通过。

Controls 使用真实 setting ID、解析后的 label/locale、类型、default、options/range 和 section/block 归属。资源选择器可映射为 fixture，但保留字段语义及差异。0、false、空字符串和未提供不能混为一谈；重复 block 保留独立值与顺序；预览辅助参数单独分组。

新组件的全部可配置字段建立消费者、默认/空值及可观察变更对应；有限选项覆盖不同语义分支，数值覆盖相关边界。模式下故意无效果的字段须测试切出模式后的恢复。不枚举全部组合；局部修改只复跑影响范围。

## 运行验证

- 动态组件区分真实数据有结果、无结果、失败/恢复与编辑器预览。编辑器 fallback 不得默默成为正式内容。
- 检查初始化/清理、重载/排序/移除、多个实例隔离和快速连续操作；本地模拟生命周期不能代替真实 Theme Editor。
- 对照来源测量 CSS viewport、iframe、父容器、内容 max-width；Storybook 管理器窗口和缩放不等于组件视口。响应式变更从非默认状态切换再返回，不仅各开一个端点页面。
- 字体核实际加载/字重/字符覆盖，图片核资源身份、解码、比例和裁切。产物在生产加载链验证，不能依赖 Vite 隐式补齐。
- 纯样式检查受影响双端外观、资源和相关状态；Liquid/schema 变化检查对应语法、引用及消费者。未做 Theme Check 如实说明，不把过滤全量输出称作局部扫描。

已经明确不检查编辑器内容的任务沿用该边界，仍核对上传角色；缺平台证据列为待验。可隔离的未发布试用按 [Draft 交付](../../dtc-delivery/references/shopify-draft.md) 进行。交接分别写已验证与待平台确认，不把本地预览、文件回读和业务接受混在一起。
