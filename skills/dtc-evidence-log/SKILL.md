# 证据记录

先消费 `dtc-context` 输出的 `targetProfile`，记录目标项目、档案版本、实际命令和交付
层级。不同项目的本地通过、预览、业务验收和发布证据不能混用。

每个事项使用一个稳定的主记录，追加阶段事件，不为实施、Review、修复和复盘重复建档。每条事件至少包含：时间、阶段、候选身份、发生了什么、依据、结果、未完成项、下一步和证据位置。

证据分为意图、来源、实现、产物、目标和结果六层。每层标记 `已验证`、`部分验证`、`待验证`、`不适用` 或 `阻断`。记录命令、退出码、范围、工具版本和非敏感环境参数；不要把完整 stdout、token、Cookie、客户记录或签名链接塞进主日志。

失败、取消、跳过和重试保留原样；后续通过不能覆盖早先失败。外部证据用 manifest 保存类型、候选引用、存储位置、哈希、可用性、保留期限和取回方法。哈希证明内容身份，不能代替访问控制或可恢复副本。

阶段交接时把“建议”“用户确认”“已实施”“已验证”“业务验收”“已发布”分开。交付摘要完成后交给 [dtc-recording-analysis](../dtc-recording-analysis/SKILL.md) 或作为下一次任务的恢复入口。
