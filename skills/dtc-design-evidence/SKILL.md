# 设计与素材取证

按视觉、交互、数据、字体和配置分别标记采用来源，静态 Figma 不能确认点击规则或数据绑定。来源可混合，不把一个维度的依据扩张成全部契约。

## 先取足以决定边界的证据

1. 固定页面/组件范围、节点链接、版本（拿不到写未知）、读取时间及桌面/移动来源。
2. 使用可用的结构化只读能力；调用连接器前遵守其工具技能。提取被截断时分区域读取；不以生成代码里的 CSS 当作原始节点数据。
3. 保存实际节点树及整体画面，初查内容、重复实例、字体/素材和效果。源图层与候选代码组件保持两棵树。
4. 页面进入 [页面拆分](../dtc-page-decomposition/SKILL.md)，单组件进入 [原子拆分](../dtc-atomic-decomposition/SKILL.md)。只补会改变边界的事实，避免未定整图方案时先为全部图层做 CSS 表。

## 按选定边界补齐

读取 [取证与资源检查](references/extraction-and-assets.md)。逐元素提取适用属性、变量绑定/解析值、实例覆写及状态，建立 extracted/partial/excluded 清单。整图可以排除内部实现条目，但保留原始证据和排除理由。

使用 [UI 规格](../dtc-ui-spec/SKILL.md) 将原值、视觉目标、实现规则分开。接口与截图冲突先查版本、节点、模式、单位和可见边界，保留双方证据，不任意选边。来源缺失只阻断受影响结论。

输出证据索引、覆盖状态、资源问题、来源到组件的映射和未知项。用户指定来源可采用已核实且无冲突的目标；不要求逐 px 重复审批。展示模式歧义、核心操作对象和破坏兼容的冲突必须先取得明确决定。
