# 生产候选与资源身份

把源码、构建输入、生成资源和部署候选分开记录。生产资源需要转译、依赖解析或打包时，在当前任务接入实际生产构建；预览服务器的隐式处理不能当作生产能力。

候选 manifest 至少绑定目标应用、源码内容（含未提交改动）、锁文件/编译配置/传递依赖、构建命令与工具版本、最终路径及内容哈希。远端专用 overlay 还绑定任务、目标、基线、策略、写入清单及最终字节；普通产物检查不能代替 overlay/ZIP 检查。

## 失效与检查

- 源码、事件 manifest、Builder、入口、公共 runtime、构建器或编译依赖改变，即使功能开关尚未开启，也应按实际构建图重建受影响候选。
- 检查最终资源的引用、imports/chunks、CSS、加载顺序及生产运行行为。缺资源、未处理源码或构建失败阻断交付，不回退到旧 dist。
- 临交付从磁盘核对真实输入和产物；候选不存在/过期时重建并复验，不编辑 manifest 哈希让旧候选通过。
- 项目有 strict candidate check 则调用已验证入口；没有时完成等价身份与依赖检查并注明是人工检查，不能编造某个工具已提供技术拦截。
- 原始日志、依赖目录、缓存、预览构建、Source Map 和凭据是否可交付按实际平台规则区分；不将整个工作目录打包。

复用检查需要输入、环境和范围仍然相同。普通 gate 在无产物时跳过不等于交付通过；本地验证、上传、回读、运行、UAT、发布分别记录。
