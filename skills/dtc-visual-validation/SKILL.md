# 视觉一致性校验

首次实现和视觉基线变化必须进行适用范围的实际画面对照。没有来源基线或正式素材只能报告部分视觉待验，不能把首次实现截图设为“正确”基线。

## 比较准备

读取 [视觉比较协议](references/comparison-protocol.md)，固定来源、候选、渲染器版本、DPR/scale、内容、状态、视口及父容器。采用 UI 规格的真实目标，computed style/布局量测只作辅助；非 Web 平台使用其布局/绘制证据。

先等待字体/图片/动画比较帧稳定，核对真实字重、字符与裁切。设计 frame、截图像素、实际视口和容器分别记录。项目宽窄基准加适用断点两侧/中间/父容器，不固定全平台的默认宽度。

## 实际核对

逐区域检查结构与间距、字体/换行、图片清晰度和裁切、背景/阴影/渐变/遮罩及叠层，覆盖默认画面与关键差异状态。自动 diff 可用时控制条件并记录容差依据；否则实际并排审阅并记录发现。只保存截图不算完成比较。

参数与组件场景可与此共用执行证据，但分别链接预期和结果。动态播放、触摸、视口切换恢复由 [组件测试](../dtc-component-testing/SKILL.md) 验证，不能用静态帧替代。

## 修正循环

记录差异区域、row/目标、实际、原因（已确认或假设）、影响、修正候选与复测。修复根因所在层，不用全局 CSS/平台覆盖补丁掩盖错误组件边界；不反改设计原值或放宽基线消灭差异。

局部改动仅比较受影响区域/状态。旧证据可以沿用，但要说明未变的输入、相关上下文和映射，不要求必须同一 commit，也不能仅因数值没变沿用。全部所需差异有结论后停止；新变化再触发。

正式素材/环境缺失交付部分功能预览，保留视觉待验。助手比较结论与用户接受是不同状态。
