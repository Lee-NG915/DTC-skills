# 验证范围编排

本技能选择“检查哪些”，不替代 [组件测试](../dtc-component-testing/SKILL.md) 的执行，也不替代 [视觉验证](../dtc-visual-validation/SKILL.md) 的画面对照。

| 改动 | 本轮检查 |
| --- | --- |
| 首次组件/子系统重写 | 完整适用 UI、参数、状态清单及直接消费者；不能只测默认样例 |
| 纯视觉/素材 | 受影响宽窄屏及状态、加载与视觉差异；几何影响命中/滚动则补行为 |
| 局部功能 | 目标规则、直接依赖、边界/异常/恢复；有稳定复现则检查修复前后 |
| 输入/配置变化 | 新字段和受影响旧项、默认/空值、语义分支、兼容与变更效果 |
| 共享逻辑/初始化/样式 | 沿真实消费者扩大；未知影响先定边界，不能按文件大小决定 |
| 生产依赖/构建链 | 当前输入重新构建，验证最终运行资源，相关集成及项目要求的 gate |
| 纯文档 | 结构、链接、契约一致性；不借机启动应用或全量业务测试 |

固定实际候选：提交加相关未提交快照、配置、来源版本、命令、测试环境和证据。未改变且仍适用的结果可以沿用，标明其原候选与有效理由；不能把旧通过数加到新执行数。skip/cancelled/not-run 不等于 pass。

按 [测试记录](../dtc-component-testing/assets/test-record.md) 将 UI、参数和场景结果分开，可共享截图/操作而不重跑三次。构建通过、预览可打开、实际运行、用户接受和发布分列；项目工具缺失使用等价验证并声明范围，不能声称原工具已运行。

通过后停止重复检查，输入改变或新证据出现再运行相关范围。交接给 [通用交付](../dtc-delivery/SKILL.md)，需要优化时使用 [优化](../dtc-optimization/SKILL.md)，监控/埋点仅在实际范围中进入其专用技能。
