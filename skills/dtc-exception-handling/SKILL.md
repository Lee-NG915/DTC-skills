# 特殊流程

先消费 `dtc-context` 输出的 `targetProfile`，使用目标项目真实的恢复命令、预览方式、
权限边界和失败分类。来源项目能回滚或回读的能力，在当前项目没有证据时保持未知。

遇到异常先保护现场：保存候选身份、差异、目标状态、失败症状和已执行动作，不覆盖原始证据。然后缩小动作到恢复或验证所必需的范围。

常见分支：

- 目标应用/环境不明：列候选和差异，不能唯一确定就不写远端。
- 需求中途变化：区分新规则与原契约缺陷，更新当前验收；核心对象或兼容承诺冲突时先确认。
- 只有截图、缺少设计版本、旧组件候选不唯一：保留可见事实，不能把静态或相似当成完整证据。
- 动态数据为空、接口失败、许可未知：分别验证回退、排除、恢复和业务交互继续。
- 共享逻辑、CI 或构建链失败：区分代码、环境、依赖、权限和暂时性原因；只做有证据支持的有限重试。
- 远端配置漂移、并发、缺少祖先、部分写入或回读不一致：终止写入，不自动覆盖、重传或晋升基线。
- 紧急故障：先恢复影响和回滚点，再处理改进；不借故障窗口顺便重构。

结束条件是“下一步可安全执行”，不要求所有未知都消失。记录已恢复、已验证、待验收和无法证明的边界，交给 [dtc-evidence-log](../dtc-evidence-log/SKILL.md)。
