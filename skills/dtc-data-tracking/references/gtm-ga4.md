# GTM / GA4 配置与既有配置保护

只在目标确实采用这些平台时读取。执行前确认账号/容器/工作区/数据流/Property、现有配置、当前用户授权与发布责任。真实 ID 和认证仅留在目标项目受控配置，公开模板不可填写真实值。

## 保留既有配置

导出并记录当前目标与共享对象基线，列出新增/更新/保留/删除及依赖。保持非本次 owner 的标签、触发器、变量、许可与目的地；测试隔离不能暂停或改写其他业务配置。工作区是配置协作范围，不应假定它隔离数据目的地；核对所有可能发送的出口。

优先使用现有容器中符合项目约定的专用工作区。多个场景共享工作区仅在同一已授权批次中明确绑定，各场景独立用例、共享变量一份。空间不足不授权删除别人的工作区。测试采样、创建版本、导入、提交、发布是独立动作，沿用当前授权而不是从“完成配置”推断全部许可。

## 导入文件与映射

需要离线导入交付时，一个目标容器维护一份共用 JSON，场景引用它；不复制一套标签。基于当前接受的事件契约与核实的工作区导出，保留共享对象和引用闭环。解析、对象身份、变量引用、触发/排除、去重、许可、目标 ID 和导入 diff 都要检查。

缺真实目标或现有共享配置时先给映射/设计草稿，不能用占位符冒充可导入文件。未实施事件不纳入可发布集合。文件生成、导入成功和发布是不同状态；变更只涉及 producer 且映射不变时复用现有文件。

## 报表与验收

从分析目标确认内置维度可复用范围、自定义定义、单位、分母、归因/关联与时间窗口。所需定义应在相应验收采样前准备；显示名调整不应通过删除重建已有定义实现，不能承诺新增字段补齐历史。

用明确标为示意的结构稿确认报表可读性，真实报表再验证。Preview/调试接收和处理后报表分别有候选/时间/环境证据；数据延迟期间记录等待条件，不重复发样污染统计。真实业务账号访问与最终签收不能由技术截图代替。

## 停止与恢复

冻结版本、计划和绑定后执行已支持动作；未知写入结果先核实部分成功，不盲重试。恢复只撤回本次拥有且内容未被他人改变的对象，超出边界先展示差异。未支持的 checker/步骤写未支持，不删需求、改历史哈希或手写 PASS。

本包不提供平台执行器、凭据加载或后台自动化。适配到项目已有工具时记录命令/版本和能力边界；有固定执行器的工程不能绕开它。平台协作语义参考 [GTM 工作区说明](https://support.google.com/tagmanager/answer/7059647?hl=en)，具体 API/导入选项以实际版本与官方说明核对。
