# 流程复盘

先消费 `dtc-context` 输出的 `targetProfile`，判断问题属于目标项目适配、通用流程、
执行遗漏、需求变化还是证据缺口。跨项目推广前保留目标项目边界和验证条件。

读取当前契约、失败/重试记录、候选身份和验证结果。区分发现环节和有证据支持的引入环节；没有历史证据就标未知。部分交接只评价已有范围，不把缺失验证当成已通过。

按问题归并多轮事件，保留每次结果。分类为：原规则未执行、规则缺失/含糊、新需求或设计变化、证据不足。已有规则没有遵守时优先修复入口和检查执行，不复制重复规则；没有调用证据不能断言 skill 没有触发。

对每条经验记录复现依据、重复程度、跨组件价值、维护成本、回归风险与置信度。结果选择“保留项目特例”“建议提升为通用规则”“待观察”“需开发决定”。缺数据不评分为零，不把风险与价值相加自动批准。

输出最小建议措辞、适用/不适用范围、受影响技能和验证场景。用户授权修改 skill 时才应用对应改动；复盘请求不自动改业务代码或部署。下一次相关任务再观察效果，不宣称改完规则就已消除返工。

复用 [dtc-evidence-log](../dtc-evidence-log/SKILL.md) 的主记录；需要把结果变成公开内容时交给 [dtc-recording-analysis](../dtc-recording-analysis/SKILL.md)。
