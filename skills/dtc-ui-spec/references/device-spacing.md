# 分设备逐项审查元素间距

读取设计稿参数时，间距不是“看起来差不多”的印象值，也不是可从一端推导另一端的默认值。必须按设备/布局变体分开取证，再按记录值实现。

## 必须拆开的证据面

每个范围内可见元素对，在每个已提供的设备与布局变体上独立审查：

- **设备**：Desktop、Mobile；只有一端时，缺失端记 `unknown`，不得用另一端填入。
- **布局变体**：同一设备若设计稿给出多种列数/卡片宽度（例如 Desktop 2 列与 3 列、Mobile 1 列与 2 列），每个变体是独立证据面，不得共用一套间距。
- **关系类型分开记录**：父级 Auto Layout `itemSpacing`、四边 `padding`、相邻节点边到边距离（from edge → to edge）、文字 baseline 间距。测得空白不等于 CSS `margin`/`gap`/`padding`。

合成示例（不作为任何项目默认值）：同一对元素（如现价与划线价）Desktop 可能是 `8px`，Mobile 单列 `4px`，Mobile 双列 `2px`。这必须分别从对应画板读出，不能把 Desktop `8px` 套到 Mobile。

## 审查步骤

1. 确认本轮范围内每个设备画板与布局变体的 node ID、画板宽度、列数/卡片宽度。
2. 列出该变体中相邻或成组的可见元素（标题与卖点、卖点与优惠码、现价与划线价、价格与分期文案、价格与加购按钮等）。
3. 对每一对元素读取：Auto Layout gap/padding（若有）+ 同坐标系边到边距离；记录 from/to 节点、边、参照 frame、单位和计算方法。
4. 将 Desktop / Mobile / 各列数变体并排对照。值相同也要写明“已分别读取且一致”；值不同必须分行，不得合并成一个单元格。
5. 接口未暴露、节点被裁切或坐标系不一致时记 `unknown`，列出待补节点，停止对该间距做实现猜测。

## 禁止项

- 用 Desktop 间距、常见设计 token（`8px`/`16px`）或“看起来紧一点”来填写 Mobile 或另一列数变体。
- 只抽一个代表卡片就宣称该组件全部间距已覆盖。
- 截图目测代替结构化测量，或把截图像素直接写成 CSS 间距。
- 为实现方便把多端间距收成单一 CSS 值；若生产必须共用，先作为待确认差异写出两端原值，不得先改设计基线。
- 缺失画板时自行插值、按比例缩放或沿用参考组件间距。

## 交给实现的数据

Review 几何关系表与 JSON 必须能回答：哪两个元素、在哪个设备/列数变体、间距原值、证据节点。开发入口只消费这些已取证值；未读取的间距保持 `unknown`，相关视觉验收不得标通过。
