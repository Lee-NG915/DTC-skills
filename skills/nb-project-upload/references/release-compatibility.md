# 发布顺序与兼容检查

适用于发布、升级 Skill 或将现有配置切到另一个站点。版本号与本地测试不证明目标接口已经部署；先确认实际目标 origin 和已获授权范围。

## 能力矩阵

| 服务端能力 | upload_projects.py | review_candidates.py |
| --- | --- | --- |
| 仅部署 `/api/ingest/projects` | 保持原默认 dry-run、`--apply`、insert-only 与批次回读 | 不可用；404 时停止候选操作，报告后端缺少能力 |
| 已部署候选接口与对应数据库迁移 | 原命令继续可用；旧回执没有 quality 字段仍有效 | GET 列表/详情、预览、PATCH 草稿、GET 精确回读 |
| 候选后端暂时回滚或不可用 | 只在用户原本授权直接收录时沿用原流程 | 保留草稿与回执，等待恢复；不降级成直接发布 |

Skill 的候选能力不包含管理员审核、正式条目修订或生产部署权限。发布新 Skill 不应扩大现有专用 token 权限。

## 发布次序

1. 负责人先完成 nb-project 对应数据库迁移（本次为 `0009_discovery.sql`）及 Worker 部署，记录实际环境、版本和回退方案。保留旧 `/api/ingest/projects` 接口。
2. 在该环境以专用凭证做有界只读核对：旧上传对一份已审核、最多20条的输入执行默认 dry-run；新客户端读取一页候选（固定20条），存在候选时读取其中一个详情。确认预检/列表/ID/version 契约，检查响应不是 HTML、重定向或404。候选列表为空只能证明列表端点可用，不能当成保存/发布验证。
3. 若发布验收包含写入，使用当前已授权的实际候选或明确标注的隔离测试数据；草稿保存与管理员审核分开验证。不要向生产灌入样例仓库或为探测接口创建假项目。`--save` 回读证明草稿存在，不能宣称已公开。
4. 后端兼容验收通过后再发布或分发依赖新接口的 Skill 版本，清楚报告旧上传和新候选两条流程的验证范围。代码提交/推送按当前授权和发布计划执行；前端公开展示/OAuth等验收沿用目标项目发布流程。
5. 切换目标或回退时，重新读取目标候选的 ID/version；不要跨站复用版本，也不要因404、401/403或质量错误改用更宽权限凭证或绕过候选审核。

## 凭证与输出

- 真实凭证仅通过现有环境或受控密钥源注入，禁止放入命令参数、JSON、仓库、聊天和报告。不要使用 `set -x`、`env`、`printenv`、`cat` 凭证文件或带请求头的网络调试输出。
- `.env.example` 只有占位值，脚本不会自动加载它。验收记录写“已配置/未配置”和状态码，不记录 token 值、前后缀或含凭证的完整命令。
- 生产仅 HTTPS、只接受 origin、拒绝重定向；仅保留客户端过滤后的错误状态和必要字段，不输出原始错误正文。候选完整输入留在受控任务目录，不粘贴到公开发布说明。

## 回读预算与结果判断

- 旧上传：每批最多20条、128 KiB；默认1次预检；`--apply` 最多“预检→写入→回读”3次请求，每次默认20秒，`--timeout` 不超过120秒。多批分别记录，不宣称跨批原子。
- 候选列表只读一页20条；确需继续时显式指定下一页。详情/预览1次GET；`--save` 为“GET当前版本→PATCH→GET回读”3次请求。候选响应上限2 MiB，输入上限128 KiB，不自动遍历全部候选。
- 写入超时/5xx/响应无法确认时保留 `writeState: unknown`，停止自动重试；先做一次同批 dry-run 或同 ID GET 核对。收到写入回执后回读失败，保留 `acknowledged`，不得改记为未写入。
- 出现409或回读版本/草稿不同，保留本地稿，重新读取并人工合并，不自动覆盖。单次恢复核对仍失败时报告待确认，不无限轮询或重复提交。
- 如需验证公开展示，限定到本次项目名/候选对应资源和必要分页；不拉取全库 export 来证明一条修改。

## 发布前本地检查

从 DTC-skills 根目录执行：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest scripts.test_nb_project_upload scripts.test_nb_project_candidates
ruby scripts/validate.rb
python3 scripts/check_public.py
git diff --check
```

测试使用合成凭证和本地响应；本地成功不能替代目标环境的部署回执。只按明确路径暂存，保留无关工作区改动，并记录依赖的后端版本与检查结果。
