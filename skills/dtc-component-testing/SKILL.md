# 组件参数与场景测试

先消费 `dtc-context` 输出的 `targetProfile`，使用目标项目实际的测试框架、Storybook
入口、fixture 边界和验证命令。目标项目没有某项运行能力时记录为未验证，不用来源
项目的浏览器、平台或服务测试替代它。

从契约和状态矩阵产生测试，不能从实现常量生成同值断言。首次新组件建立完整适用清单；局部变更由 [范围选择](../dtc-scoped-validation/SKILL.md) 裁剪。数据和能力不存在时不制造请求、动画或远端保存流程。

## 先规划，后执行

实现前已有预期和适用场景；实现后把它们绑定到真实组件/预览入口。选择项目实际工具：单元验证纯计算/映射，组件验证输入和事件，集成验证消费者/适配器，界面测试验证真实交互和绘制。不强制某个测试框架。

使用 [检查与断言清单](references/test-contract.md) 完成首次适用覆盖，复用 [记录模板](assets/test-record.md)。新增字段逐项检查身份、默认/空值和消费者，并有实际变化结果；可共用一个场景验证多个字段，不能漏项或遍历无差异的笛卡尔积。

## 三类结果分开

- UI 还原交给 [视觉验证](../dtc-visual-validation/SKILL.md)，数值和截图是不同证据。
- 参数检查检查输入/配置到消费者的变化、条件模式、有效零值和恢复。
- 场景检查检查组合内容、转换、快速操作、空/失败/恢复、双端切换和实例隔离。

三类可并行或共用操作，不要求视觉通过后才能测行为。预览已声明、测试文件已建、断言已执行和结果通过分别记录。服务启动或页面可打开不能证明业务通过。

## 回归与退出

追踪旧消费者、共享初始化、全局样式和构建输出。新增文件不证明隔离；旧输入缺新增字段、多实例新旧混用按风险覆盖。对失败保存症状、候选和重试，稳定逻辑缺陷修复前后复跑同一范围；纯样式不要求逻辑 RED。

适用项未执行为待验/阻塞，不伪装不适用。全部所需检查有结论后交接，未变化且证据有效不重复测试。真实集成与 fixture 模拟分开。
