# 业务交付 Review

先复用当前上下文和已有需求，固定使用者、准备完成的任务/决定、交付阶段、候选、范围及排除项。用一句话说明“在什么场景，看到或执行什么，随后能作出什么判断”。资料不足时先完成可核实部分。

依据分为通用原则、当前已确认约束、角色/阶段偏好。偏好注明来源和适用范围，不推断个人权限，不把历史项目的审批人、评分阈值或运营习惯推广为通用门禁。

## 按实际业务任务核查

| 检查 | 可观察依据 |
| --- | --- |
| 决策关联 | 一次实际输入能产生有用结果；字段多或事件多不等于可用 |
| 对象可辨 | 页面、内容、实例、位置和动作可读，同名对象能区分；技术键可追溯 |
| 口径可信 | 单位、范围、分母、去重和时间窗明确；零/未知/未采集分开 |
| 日常可用 | 使用者的普通账号能打开、筛选和理解；完整清单验证分页/导出行限 |
| 场景与证据 | 代表性真实输入和边界对应当前候选；本地、接收、报表、签收分层 |
| 维护成本 | 新增配置、解释、维护和恢复工作有归属，收益有依据 |

页面/组件核对真实内容、优惠和购买对象、空值/长内容及操作后的结果。看板或埋点使用 [分析验收](references/analytics.md) 和 [数据追踪](../dtc-data-tracking/SKILL.md)。工具/性能比较同条件的实际步骤和测量，不默认引入供应商或固定分数。

## 输出

复用当前记录，按业务影响列出：位置与证据 → 触发场景 → 业务后果 → 最小修正 → 责任角色 → 可观察验收。未知项写未验证，不当作已发生故障。分别列出应保留的既有能力、关键缺口和偏好建议。

结论为通过、限定范围通过、需修正或证据不足，并注明可推进的阶段。只有当前授权包含实施时才落实修正；审查不授予平台操作、发消息或发布权限，不自动增加审批人。
