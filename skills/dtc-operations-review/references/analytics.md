# 分析交付验收

从约定业务问题反推报表，不先堆事件或字段。先展示可读表头和标为示意的代表值，让使用者能解释一行及一个比例，再决定采集缺口。显示名调整、查询口径修正和采集变更分别评估。

| 维度 | 检查 |
| --- | --- |
| 事实与单位 | 点击、请求、到达、界面更新、订单成功分开；主动动作与自动行为分开 |
| 对象可辨 | 稳定技术 ID 用于关联，可读名称/路径用于识别；同名/重排/隐藏实例有解释 |
| 去重与分母 | 人数在目标粒度重新去重，不把分组人数相加；占比写父集合/过滤/时间窗 |
| 历史语义 | 旧字段只映射可证明含义；新增字段不承诺补齐历史；未知不填 0 |
| 全量与零值 | 全部已观测对象不同于全部实际配置对象；零点击需点位目录和有效窗口 |
| 时效 | 业务时区、数据截止、刷新与容许延迟可见；最大事件日期不等于当天完整 |
| 环境与权限 | 样本、正式、未知环境分开；实际业务账号可访问；分页/导出核总数和行限 |
| 证据 | 从获准交互追至下游明细、处理后结果和展示；模拟数据不能充当正式接收 |

同日期/市场/设备等条件下核对图表过滤及粒度。没有样本、分母、周期或可比条件时不声称掉线、用户流失或因果改善。跨设备身份、归因和精确动作配对需要平台实际支持，不能从匿名 ID 推断真人。

复用现有字段和能力优先；只为已批准且现有信息回答不了的问题提出新增采集。用户排除自动监控等范围时保留排除项。输出限定结论、缺口及下一责任角色，未实测的平台导航链接不得冒充验收证据。
