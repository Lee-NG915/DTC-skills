# 记录、变更分类与恢复

业务需求归所属应用，公共模块设计归公共架构，操作方法归指南，实施事实归同主题记录。使用稳定文件名，日期写正文；独立需求/模块才新建，不为实施、Review、修复各建一套。已有 requirementId、runId 和冻结证据保持原身份。

| 分类 | 判断依据 |
| --- | --- |
| 澄清 | 明确原意，未改变可观察结果 |
| 需求/设计变化 | 新确认改变范围、行为或采用目标 |
| 取证修正 | 更正测量/来源解释，原始证据保留 |
| 实现缺陷修正 | 当前实现未达到原有有效契约 |
| 环境/资料缺口 | 无足够证据判断，不臆测已发生故障 |

事件关联前后基线、来源、影响到的文档/实现/测试和真实结果。没有历史依据时注明补录时间与未知项，不从当前文件编造过去阶段。

当前摘要放目标/目录/分支、有效决定、候选与证据、已完成/待验收、阻塞及下一动作；恢复先读摘要和下一步必要证据，再核对实际工作区，不重载全部历史。摘要是检索入口，不是授权。

UI 规格、实现、视觉还原、配置参数和组合场景各记状态，可复用同一次执行证据。所有结果附被测候选与适用范围；输入变化后的旧结果保留为历史。预览可访问、上传、回读、平台服务、真实编辑器、业务接受及发布不能互相代替。

主日志保留精简结论和证据索引；原始 stdout/trace/截图/快照默认在受控忽略目录或 artifacts。记录内容哈希、取回方式、责任角色、有效期和可用性，不把哈希当脱敏或恢复副本；保留期按项目政策决定，不继承其他公司的期限。不能改后缀把原始输出绕进 Git。

失败保留，通过另记；重复现象没有验证原因不能写成确认根因。复盘引用具体事件，区分执行遗漏与规则缺失，提出最小改进与下次观察条件。没有调度回执不写会话结束后自动跟进。
