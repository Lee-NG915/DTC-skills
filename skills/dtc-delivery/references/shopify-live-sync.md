# Shopify Live → 本地源码

仅用于明确授权的 Live 同步。先绑定准确应用、店铺和当前 Live 角色，核对未提交改动；主题根与 Git 根可以不同。拉取进入隔离目录，不直接覆盖应用源码。

## 四份输入

- S：当前源码及未提交快照，供并发检查和恢复。
- B：有来源证据的已接受 Live 共同祖先，绑定店铺、主题身份和完整清单。Git HEAD、主题创建时间或当前 Live 不是默认祖先。
- L：由 S 当前构建得到的可部署主题，包含生成资源。
- R：本次准确 Live 的完整快照，记录角色、内容及获取完整性；角色变化先重新核实。

没有可靠 B 时先比较/取证，可审阅具体覆盖方案，不伪造三方祖先。代码和定义按 B/L/R 合并：单方修改保留、同值去重、不相交变化可合并；同字段竞争、顺序、删除/修改或无法解释的生成文件保持待裁决。时间只作线索，不按 mtime 自动选择赢家。

## 配置与源码回填

先分类代码/设置定义、运营保存值、模板布局/市场配置、生成资源及未知文件。按当前项目已确认的配置归属处理；若采用 Live 运营配置优先策略，仍展示将舍弃的本地差异，并沿用或取得对应内容决定。通用三方合并无冲突不能证明符合业务意图。

在源码副本中应用已接受普通文件及删除，验证引用、配置/schema 和受影响回归。生成资源的远端变化不能直接忽略：保留原始字节，定位对应源代码并移植，再构建验证。仅合并压缩产物不是可持续源码交付；缺源或意图无法判断时阻断受影响部分。

重建后，普通文件及删除必须与已接受结果一致；生成资源可以字节变化，但语义证据须绑定源哈希、预期/实际产物、当前候选及验证结果，同时覆盖已接受远端行为和本地开发行为。普通文件不适用这个例外。

正式应用前重查 S 和 R 的身份/内容，漂移则重算；只应用当前授权的应用及确有必要的公共源变更。最终真实源码再次构建验证后才更新已验证基线。记录冲突、决策与依据、生成源映射、验证和剩余缺口。

本流程允许已接受的 Live 内容回填源码；[Draft 交付](shopify-draft.md) 的专用 overlay/回读不得回填。同步不自动 commit、push 或发布；本技能包没有 merge engine、拉取器或通用反编译器，使用项目现有能力或明确记录手工执行。
