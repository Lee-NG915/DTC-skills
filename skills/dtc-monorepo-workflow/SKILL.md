# 多应用工程工作流

先消费 [dtc-context](../dtc-context/SKILL.md) 的目标档案。公共工程任务不虚构 app；应用任务逐个解析真实应用、源码根、环境归属和消费者。路径、命令及策略取自目标工程，不从另一应用复制。

## 归属与隔离

- 为每个受影响应用记录 appRoot、构建入口、产物目录、配置加载来源和验证范围。涉及远端时才追加 store/tenant、目标 ID、角色与任务绑定；配置存在不等于授权。
- 根公共技能、项目规范与应用规则冲突时，核对目标工程的优先级；迁移快照和生成镜像不作为第二维护源。只修改已授权路径，公共变更沿实际消费者评估影响。
- 凭据使用所属应用的安全环境来源；不回退到根环境、不跨应用继承 token、CLI 缓存或历史 Draft。发现归属错误先指出路径及修复方案，不输出实际值。
- 新入口/配置同步项目登记、消费者校验、无真实值示例及拒绝无效配置的测试；不通过放宽检查、改冻结哈希来获得通过。

## 工程操作

只有目标工程采用 Nx 时读取 [Nx 适配](references/nx.md)。其他构建器沿用项目能力；不得为使用本技能而安装 Nx。新增结构先查现有生成器，跨仓导入先形成路径、依赖和历史保留计划。

使用 [Git 与协作记录](references/git-collaboration.md) 核对分支、upstream 与 worktree。单应用任务在整仓 Git 中按明确路径暂存；不重置共享分支来同步应用。

## 构建与交接

使用 [生产候选契约](../dtc-delivery/references/production-candidate.md) 区分源码、生成资源、预览与实际可部署文件。公共 runtime/依赖/构建链改变时检查全部实际消费者；本地 build 不暗含上传。

执行工程实际要求的结构、环境和集成检查；不存在相应工具时列出手工检查结果及缺口，不能照抄别的仓库命令。交付上下文、路径范围、命令结果、候选身份和仍未验证的层级。
