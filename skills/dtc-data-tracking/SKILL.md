# 数据追踪

只有在事件、公共字段、许可判断、发送 transport、监控或分析可行性变化时使用此 skill。分析目标应在实施前明确；新链路先形成场景方案并由开发人员 Review，已有决定不重复确认。先定义业务场景和事件语义，再确定 producer、字段契约、跨字段 Builder、平台适配器和下游映射的职责。

一个事件可以服务多个场景，一个场景也可以复用多个事件；不要为每个页面复制发送逻辑。场景范围至少覆盖：正常发送、排除条件、缺字段降级、许可允许/拒绝/未知、撤回、不补发、重复初始化、下游失败和业务交互继续。

按受影响场景运行最小单测/浏览器验证；公共 runtime、初始化或构建链变更时扩大到所有消费者。`queued`、本地调用、模拟请求或 DebugView 只证明对应层级，不证明分析平台已处理或报表可用。

输出事件/字段/映射变化、测试范围、真实接收缺口和待业务验收项，交给 [dtc-evidence-log](../dtc-evidence-log/SKILL.md)。

同步维护场景到事件/字段/下游映射和测试范围登记；事件修改反查所有引用场景。不能把独立业务事件强行组成必经漏斗。生产输入变化时重建，真实接收与处理后报表覆盖分别验收。
